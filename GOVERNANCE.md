### Before opening an Issue or Pull Request

Please search existing issues first, remove secrets and private data, and choose the narrowest applicable template. Public issues and pull requests must never contain credentials, private keys, `.env` contents, proprietary source code, unredacted personal paths, or details of an unpatched vulnerability.

For a change larger than a typo, explain the context, problem, proposed solution, acceptance criteria, dependencies, risks, and security/privacy impact. A rule change additionally requires a stable rule ID, fixtures, regression tests, deterministic behavior, safe evidence, remediation guidance, and documentation.

### Sebelum membuka Issue atau Pull Request

Cari issue yang sudah ada terlebih dahulu, hapus secret dan data privat, lalu pilih template yang paling sesuai. Public issue dan pull request tidak boleh berisi credential, private key, isi `.env`, proprietary source code, personal path yang belum disanitasi, atau detail vulnerability yang belum ditambal.

Untuk perubahan yang lebih besar daripada typo, jelaskan context, problem, proposed solution, acceptance criteria, dependencies, risks, dan dampak security/privacy. Perubahan rule juga wajib memiliki stable rule ID, fixture, regression test, perilaku deterministic, evidence yang aman, remediation, dan dokumentasi.
